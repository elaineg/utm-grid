# UTM Grid
Purpose: a no-account bulk UTM campaign URL builder for marketers — edit 20–50 links in a spreadsheet-style grid with naming-convention linting (both governed allowed-VALUES and a structured campaign-name composition template) and CSV round-trip; client-side by default, with an optional server-persisted shared Team Workspace addressed by a secret link, a shareable read-only style-guide page, a two-way pre-launch Review & Approval sign-off loop per workspace, and a device-local "My Workspaces" index so a marketer never loses a workspace's secret link.
Problem: A demand-gen / lifecycle marketer launching a campaign each week must tag 20–50 links with consistent UTM parameters across channels (email, paid social, organic social, partners), and a single casing/spelling inconsistency silently splits campaign data in GA4 — discovered only weeks later during reporting.
Beats alternative: Teamcamp UTM Bulk Link Creator (free, no account) — the best free bulk tool — requires hand-typed pipe-delimited per-row overrides, has no CSV import (links already live in a campaign planning sheet), no required-param or cross-row consistency linting (only a lowercase checkbox), and no presets. UTM Grid replaces pipe syntax with an editable grid, adds CSV import AND export for round-tripping with the existing campaign sheet, lints conventions as you type — including flagging near-duplicate values across rows (e.g. `spring_sale` vs `Spring-Sale`), the GA4 data-splitting failure no existing free tool catches — and saves channel presets in localStorage. Cuts a weekly 30-link batch from ~15 min to ~5 min. For teams, the shared Team Workspace adds a no-account, two-way **Review & Approval** pre-launch sign-off: a teammate marks each link Approved or Needs-changes (with a note) and an above-grid roll-up shows "is this batch signed off yet" — replacing the back-and-forth Slack/email "are these UTMs final?" thread that no free UTM tool offers, the team/pro pay-value.

Core flows:
1. **Edit links in a grid with lint-as-you-type.** The page opens on an editable spreadsheet-style grid: one row per link, columns for base URL, utm_source, utm_medium, utm_campaign, utm_term, utm_content, and a read-only generated-URL column that updates live. Rows can be added, duplicated, and deleted. Linting runs on every edit and marks offending cells with a visible warning (icon/color + hover or inline message): (a) required params missing — utm_source, utm_medium, utm_campaign required by default, toggleable; (b) case/space rules — lowercase-only and no-spaces on by default, each toggleable; (c) cross-row consistency — values in the same UTM column that match after normalizing case and separators (`-`, `_`, space) but differ literally are flagged on every affected cell, naming the conflicting variants; (d) **off-spec values (governed UTM taxonomy)** — a **UTM Spec panel** lets the user define, per UTM field (utm_source / utm_medium / utm_campaign / utm_term / utm_content), a list of canonical **allowed values** (the org's taxonomy). When a field has a non-empty allowed-value list: the cell input offers those values as autocomplete suggestions (HTML datalist), and any non-empty cell value not in the list (compared case-insensitively) is flagged with an **off-spec** lint warning that names the **nearest allowed value** (closest by normalized match, else shortest Levenshtein edit distance) and offers a one-click **"Fix to <nearest>"** action that sets the cell to that allowed value and re-runs lint. Off-spec linting is additive to the case/space/cross-row rules and toggleable like them (a single "Enforce UTM Spec" toggle; when off, no off-spec warnings and no datalist suggestions). A copy button per row copies the generated URL; a copy-all button copies all generated URLs. **Responsive layout (mobile card view, ≤640px):** the grid is purely CSS-responsive (Tailwind breakpoint classes — no JavaScript viewport detection, so no SSR/hydration mismatch and no double-mounted dual-layout component). On wide viewports (`sm` and up) the spreadsheet-style table renders unchanged. On narrow viewports (≤640px) each row renders instead as a vertical **card**: every UTM field is a stacked label-over-input pair (so no horizontal scrolling is needed to reach a field), the generated-URL and per-row copy/duplicate/delete/select controls are full-width and tap-friendly (≥44px touch targets), and lint warnings render inline under their field. All controls remain reachable and hittable on a phone — no sticky/overlay element occludes a checkbox or button. The bulk toolbar, Campaigns/UTM Spec/preset panels, Import/Export, and "Copy share link" all stack and stay reachable on mobile. A shared grid opened from a copied share link renders in this card view on a phone and is fully legible and usable. **Bulk row/column operations (power-edit, fully client-side):** each row has a selection checkbox plus a header "select all" checkbox, so bulk actions target either all rows or just the currently-selected subset (when no rows are selected, bulk ops apply to all rows). A bulk toolbar exposes two operations, each on a chosen UTM column (utm_source / utm_medium / utm_campaign / utm_term / utm_content): (a) **Set column** — set that field to one entered value across the targeted rows in a single action (an empty value clears the field across them), so a weekly 20–50 link batch that shares utm_campaign/source/medium is tagged in one move instead of per-row; (b) **Find & replace in column** — replace a value or substring in that column across the targeted rows (e.g. `Spring-Sale`→`spring_sale` everywhere). Both operations run instantly, persist to localStorage like the rest of the grid, trigger no network request, and re-run linting immediately so cross-row consistency and case/space warnings update on the affected cells. The bulk controls use verbs distinct from the per-row controls (Set / Replace vs the row Dup / Delete) so they never read as duplicate controls. **QR codes for tagged links (per-row + bulk, 100% client-side over the existing generated-URL column):** each row whose generated URL is valid/non-empty exposes a discoverable inline **"QR"** button near that row's per-row copy control; clicking it opens a small inline popover/panel that renders the QR (generated client-side with the `qrcode` lib, in a client effect / on the click — NEVER in a useState lazy initializer, no window/document reads during render) for that row's FULL generated tagged URL including all `utm_*` params, with **"Download PNG"** and **"Download SVG"** actions; the QR encodes the EXACT generated URL string. A bulk **"Download QR codes"** action (verb DISTINCT from every existing control — Copy share link / Create shared workspace / Copy workspace link / Share style guide / Run Launch Check / Audit URLs / Import CSV / Export CSV / Set column / Find & replace in column — so it never reads as a duplicate) uses the SAME row-selection model as the other bulk ops (targets the selected rows, or ALL rows when none are selected), generates a QR for every targeted row that has a valid generated URL, and downloads a **ZIP** (built with `jszip`) containing one PNG per row named by a STABLE scheme — zero-padded row number + slugified `utm_campaign`, falling back to just the zero-padded row number when `utm_campaign` is empty — PLUS one printable **"contact sheet" PNG** (a canvas-drawn grid of all the generated QR codes, each labeled with its row number + `utm_campaign`, or the generated URL when campaign is empty) so a marketer can print a single sheet. Rows with empty/invalid generated URLs are SKIPPED (never crash, never silently dropped) and the count is surfaced as e.g. **"N QR codes generated, M rows skipped — no valid URL"**. Both the per-row QR and the bulk export are FULLY CLIENT-SIDE: they trigger ZERO network requests after initial page load (DevTools Network-verifiable), and work on BOTH the main builder AND `/w/<id>` workspace pages where they are **READ-ONLY-SAFE** — QR generation only reads already-loaded grid state and does NOT mutate the grid, NOT autosave, NOT POST/PUT. At 375px the QR button, the popover, and the "Download QR codes" control are reachable/operable with no horizontal scroll and not occluded by any sticky/overlay element; the popover z-stacks above cell affordances and any rendered QR panel stacks BELOW at constrained width, never squeezing the editable grid columns off-screen. A cold open shows no QR popover until a QR button is clicked.
2. **CSV round-trip with an existing campaign sheet, plus Paste & Audit of existing tagged URLs (inbound counterpart) and a whole-grid Launch Check compliance report.** An Import CSV button accepts a file upload, parses it in the browser, shows a column-mapping step (map CSV headers to base URL and each utm_* field; headers matching field names are pre-mapped), and populates the grid — lint warnings apply immediately to imported rows. An Export CSV button downloads a file with one row per grid row containing the base URL, every utm_* column, and the full generated URL. Exporting and re-importing the same file reproduces the grid exactly. **Paste & Audit existing UTM URLs (the audit-INBOUND counterpart to the build-OUTBOUND grid/CSV flows):** a clearly-labeled **"Audit URLs"** entry point on the main builder — verb DISTINCT from "Import CSV" so the two never read as the same control — opens a textarea where the user pastes full, already-tagged URLs, one per line (inherited from a sheet or pre-launch QA). On submit each non-empty line is parsed **entirely in the browser** (no network): split into the base URL (scheme+host+path with any non-utm query params preserved, e.g. a base `?ref=1` is kept) minus the `utm_*` params, and the utm_source / utm_medium / utm_campaign / utm_term / utm_content values are extracted from the query string into their columns. Malformed lines (not parseable as URLs) are counted and named in a **parse summary** (e.g. "1 line skipped") — never silently dropped, never a crash; valid lines still import. Parsed rows populate the grid using the **SAME unsaved-edits guard** the share-link / Open-campaign load uses (confirm before replacing a dirty working grid; append-vs-replace is acceptable), and linting runs immediately on the imported rows — missing-required, case/space, cross-row consistency, AND off-spec vs the current UTM Spec — exactly as for typed input. Works in the mobile card view (≤640px).
   - **Launch Check (whole-grid compliance report — pre-launch QA over what's already in the grid).** A prominent, clearly-labeled **"Run Launch Check"** action — verb DISTINCT from "Audit URLs", "Import CSV", and from all share actions ("Copy share link" / "Create shared workspace" / "Copy workspace link" / "Share style guide"), so it never reads as the same control — available on BOTH the main builder and on `/w/<id>` workspace pages. The existing inline lint-as-you-type marks one cell at a time; Launch Check answers the different question "is the WHOLE batch ready to ship?" by running the **full existing lint suite across ALL current grid rows at once** (reuses `lintRows` — NO new lint logic) and rendering a **Compliance Report** as a full-width SUMMARY panel ABOVE the grid in normal page flow (NOT a side panel, NOT inside grid columns). The report shows: **total links checked**, **# passing** (rows with zero warnings), **# with issues**; then issues grouped by issue type/field, each line naming the **row number + which cell/field + the existing lint message** (required, lowercase, no-spaces, inconsistent, off-spec, invalid-url, base-utm, off-template). A fully-clean grid shows a clear **"All N links pass"** success state. **Export:** a **"Download report (CSV)"** button downloads a CSV with one row PER violation — columns: row #, base URL, field, value, issue type, message (a single all-clear row when the grid is clean); a **"Copy summary"** button copies a plain-text summary to the clipboard with a peripherally-unmissable **"Copied!"** confirmation (green-fill-in-place + aria-live). **Strictly READ-ONLY of current state:** Launch Check NEVER mutates the grid, NEVER autosaves, and makes NO network request on the builder and NO POST/PUT on `/w/<id>` (it reads the already-loaded workspace state with no extra write — critical so the report can't clobber a workspace). A cold open triggers no Launch Check and no network. **Mode-aware copy:** any "client-side / no network" wording is accurate on the server-backed `/w/<id>` page. Reuses existing state + lint engine — NO new server schema/table, no new credential. Reachable and operable in the mobile card view at 375px (scorecard panel + both export/copy buttons stack, no horizontal scroll, no sticky/overlay occludes the controls); desktop ≥640px unchanged.
3. **Named saved state in localStorage — channel presets AND a Campaigns library.** Two complementary kinds of reusable saved state, both 100% client-side (localStorage only — no accounts, no server, no network):
   - **Channel presets:** save the current values of any subset of UTM fields (e.g. utm_source=facebook, utm_medium=paid_social) as a named preset ("Paid Social"), then apply a preset to a selected row or to new rows so weekly batches start pre-filled.
   - **UTM Spec (governed taxonomy):** the per-field allowed-value lists and the "Enforce UTM Spec" toggle persist in localStorage alongside presets/campaigns, are saved INSIDE each named campaign's state, and ride inside the share-link fragment (Flow 4) — so opening a saved campaign or a shared grid adopts that grid's UTM Spec, propagating the team's taxonomy. This is the convention-propagation loop: one marketer defines the org taxonomy and shares it; the teammate's grid then enforces it.
   - **Campaign Naming Template (governed STRUCTURE of utm_campaign — distinct from UTM Spec, which governs allowed VALUES per field):** a **Naming Template panel** — a first-class, visually DISCOVERABLE sibling to the UTM Spec panel (not buried) — lets the user define an ORDERED list of named **segments** for `utm_campaign` (e.g. segment 1 `quarter`, segment 2 `channel`, segment 3 `audience`) plus a chosen **separator** (default `_`, also `-`). Each segment optionally carries an **allowed-token list** (reusing the UTM Spec allowed-value-list UX pattern). Segments can be added and removed (reorder is a nice-to-have). A per-row **"Build name" composer** offers one control per segment — a dropdown when that segment has an allowed-token list, free text otherwise — and assembles a compliant `utm_campaign` joined by the separator (e.g. quarter=`2026q3`, channel=`paidsocial`, audience=`retargeting` → `2026q3_paidsocial_retargeting`), writing it into that row's utm_campaign cell and re-linting. A single **"Enforce naming template"** toggle (independent of "Enforce UTM Spec"): when ON, any NON-EMPTY utm_campaign value not matching the pattern gets an **off-template** lint warning that names exactly what's wrong — either (a) wrong segment count after splitting on the separator (e.g. "expected 3 segments, found 2"), or (b) a segment whose token is not in that segment's allowed-token list (naming the offending segment + its allowed tokens). This is ADDITIVE to the case/space/cross-row/off-spec rules and toggleable independently; when OFF there are no off-template warnings and no composer enforcement. The template (segment defs + separator + enforce toggle) persists in localStorage alongside presets/UTM-Spec, is saved INSIDE each named campaign's state, and rides inside the share-link fragment AND the Team Workspace (/w/<id>) payload (another field in the same serialized grid+spec state — no new schema, no new credential, free-tier) — so opening a saved campaign, a share link, or a workspace adopts that grid's naming template. This extends the convention-propagation loop from allowed-VALUES to campaign-name STRUCTURE. Fully client-side (no network for template/composer/lint), and reachable/operable in the mobile card view at 375px with no sticky/overlay occluding controls.
   - **Campaigns library (personal-accumulation layer):** save the ENTIRE current grid — every row (base URL + all utm_* fields), the active lint-rule toggles, AND the current UTM Spec (allowed-value lists + enforce toggle) — as a NAMED campaign (e.g. "Black Friday"), building up a reusable library the user returns to each week. A Campaigns panel lists saved campaigns by name with their link count and last-saved time. From it the user can: **Open** a campaign (load it as the working grid, with the same unsaved-edits guard the share-link load uses — confirm before replacing a dirty working grid), **Save as campaign** (name + save current grid; saving under an existing name updates it after a confirm-overwrite), **Duplicate** a campaign (copies to "<name> copy"), and **Delete** a campaign (confirm). A first-ever visit shows an empty library with a one-line hint.
   - Presets, the Campaigns library, lint-rule toggles, and the live working-grid rows themselves all persist in localStorage across reloads (a refresh mid-edit never loses the batch). Opening a saved campaign or a share link never silently clobbers unsaved working-grid edits.
   - From the Campaigns panel the user can also **Rename** a campaign: clicking Rename reveals an inline pre-filled name field (Enter commits, Esc cancels); the campaign's id, rows, and settings are unchanged; renaming to the same name is a no-op; renaming to a name that collides with a different campaign prompts a confirm-overwrite dialog before replacing. A search/filter input at the top of the Campaigns list filters visible cards by name substring (case-insensitive).
4. **Share & sync the grid — one-shot link OR live Team Workspace.** Two rungs of the same sharing ladder; pick the level of persistence the team needs.
   - **Rung 1 — one-shot share link (client-side, no account, no server, unchanged).** A "Copy share link" button encodes the entire current grid state — every row's base URL and all utm_* fields, the active lint-rule toggles, AND the current UTM Spec (per-field allowed-value lists + the "Enforce UTM Spec" toggle) — into the URL fragment (hash), compressed, and copies the full shareable URL to the clipboard with a peripherally-unmissable "Copied!" confirmation. Nothing is sent to any server (the state lives only in the hash). Opening a URL that contains a share fragment rehydrates the grid to exactly the shared state — including the shared UTM Spec, which then governs off-spec linting and datalist suggestions for the visitor — and shows a "Loaded shared grid (N links)" confirmation; the visitor's own localStorage is not overwritten until they edit. This turns a single-user batch into a team handoff — a marketer sends a teammate a link instead of a CSV — while preserving the zero-network privacy prop. This rung is a frozen snapshot: opening it does not sync back.
   - **Rung 2 — Team Workspace (server-persisted, secret-link, last-write-wins, no auth).** A separate **"Create shared workspace"** action (distinct from "Copy share link") POSTs the current workspace payload — the grid rows (base URL + all utm_* fields), the active lint-rule toggles, and the current UTM Spec (per-field allowed-value lists + "Enforce UTM Spec" toggle) — to the server (POST `/api/workspace`), which stores it in a Turso DB and returns a freshly generated, unguessable secret workspace id (≥ 22 url-safe chars). The app then navigates to `/w/<id>` and copies the full `https://<host>/w/<id>` link to the clipboard with a peripherally-unmissable "Copied!" confirmation. The personal **Campaigns library is NOT part of the workspace payload** — the workspace is one shared grid + its taxonomy (the team source-of-truth); the Campaigns library stays local. **`/w/<id>` route:** opening this URL fetches the workspace data from the server (GET `/api/workspace/<id>`) **via a fetch effect — never a useState lazy initializer** (avoids the SSR/hydration mismatch lesson) — and renders the full utm-grid editor seeded with that exact data (rows + lint toggles + UTM Spec). The page shows a clear **"Team Workspace — synced" banner** with a "Copy workspace link" button. Edits to the grid/spec on a `/w/<id>` page **autosave** to the server (debounced ~800ms PUT `/api/workspace/<id>`), **last-write-wins** (no merge, no conflict UI, no presence, no realtime). Opening the same `/w/<id>` link on another device/browser shows the same data on load / after refresh. A workspace whose id doesn't exist shows a clear **"Workspace not found"** state with a link back to the main builder — never a crash or blank. **The visitor's own localStorage working grid is NOT touched by being on a `/w/<id>` page** — workspace state is separate from the local default grid. **Privacy posture:** no login, no email, no account; the secret URL is the capability; the server stores ONLY the workspace payload plus a user-typed editor label (no IP, no identity, no cookies — zero-identity).
   - **Workspace History & Attribution (makes last-write-wins SAFE — `/w/<id>` only).** Because workspace autosave is last-write-wins with no merge, this rung keeps a server-side **version history** so a clobbered grid is always recoverable, plus lightweight human attribution. Each autosave (PUT) appends a version SNAPSHOT to a Turso table `workspace_versions(id INTEGER PRIMARY KEY AUTOINCREMENT, workspace_id TEXT, data TEXT, editor TEXT, created_at INTEGER)`; creating a workspace seeds **version 1**. History is **CAPPED at ~25 newest versions per workspace** (oldest pruned) to stay tiny on the free tier; a save identical to the latest version need not create a new version (dedupe). A **"History" panel on `/w/<id>`** lists versions newest-first, each with a relative time ("2 min ago") and the editor label; the user can **Preview** a version (read-only view of that version's grid/spec, no overwrite) and **Restore this version** — restore is **NON-DESTRUCTIVE**: it PUTs the chosen version's data back as the new current state (reusing the autosave path), which itself becomes a new version, so the clobbered state is never lost. **Optional attribution (anonymous-first):** a small **"Editing as: [name]"** control on `/w/<id>` lets the visitor set a display name, stored in **localStorage per browser** (default e.g. "Anonymous"); it is never required, never blocks editing, and creates no account/email. The name rides with each autosave (becomes that version's `editor`), and is shown in the synced banner ("last edited by <name> <relative-time>") and on each History entry. **GET `/api/workspace/<id>/history`** returns the capped version list (metadata + data) for the panel; **restore reuses the existing PUT autosave path** (restore = PUT the chosen version's data). **Hard invariants:** none of this exists off `/w/` pages — the main builder, Rung 1 one-shot share link, Campaigns library, presets, UTM Spec, bulk ops, and CSV are all unchanged and a cold open triggers no history; a brand-new workspace has exactly one initial version and an otherwise-empty history; anonymous-first is preserved (display name optional and local, no auth, no email, no server-side identity beyond the free-text editor label); free-tier (Turso only, history capped per workspace, no new credential).
   - **Team UTM Style Guide (shareable READ-ONLY governance reference — `/w/<id>/guide`).** A separate route that renders the workspace's accumulated standard as a single legible, human-readable, link-shareable reference page for anyone who needs to KNOW how this team tags links (a teammate, an agency, a contractor) WITHOUT editing. It renders **read-only FROM THE EXISTING WORKSPACE PAYLOAD** (reuses GET `/api/workspace/<id>` — no new schema, no new table, no new credential): (a) the **UTM Spec** allowed-values per field (utm_source/medium/campaign/term/content); (b) the **Campaign Naming Template** — ordered segments + separator + per-segment allowed tokens — WITH a worked example `utm_campaign` assembled from the template; (c) the **active lint rules** (required params, lowercase-only, no-spaces, Enforce UTM Spec, Enforce naming template — whichever are ON); (d) the casing/separator conventions in plain language. The page is **TRULY READ-ONLY**: it makes **NO PUT/POST, never autosaves, never writes to the workspace or localStorage** — it only GETs (critical: a read-only page that writes back can clobber workspace state). A clear, **prominent CTA** ("Open the editable workspace" → `/w/<id>`) invites the reader into the editor — the viral on-ramp turning a non-user recipient into a user. **Discoverability:** the editable `/w/<id>` page exposes a first-class, visually distinct **"Share style guide"** action (NOT buried at the bottom) that copies the `/w/<id>/guide` link with a peripherally-unmissable **"Copied!"** confirmation. A workspace id that doesn't exist → the guide shows a clear **"Workspace not found"** state with a link back to the builder (mirrors `/w/<id>` not-found), never a crash/blank. **Mode-aware copy:** any privacy/"client-side" wording on the guide is accurate for a server-backed page (no stale zero-network claims). Free-tier: Turso only (reuses workspace data), no RESEND, no Stripe, no new env var.
   - **Review & Approval — two-way pre-launch sign-off (`/w/<id>` only).** Turns the one-way shared workspace into a two-way review loop so a batch gets a clear pre-launch gate before it ships. On `/w/<id>`, any teammate opening the link can act as a **REVIEWER with NO account**: they set a **reviewer name once** (anonymous, frictionless, stored in localStorage key `utm-grid:reviewer-name`, mirroring the existing `editor-name` control — NEVER required, NEVER blocks the cold-open editable flow). Per link row, a distinct **Review control** lets the reviewer mark the row **Approved** or **Needs changes** with an optional short **note**; the verbs are deliberately **"Review"/"Approve"/"Needs changes"** — NOT "Audit"/"Check" — so they never read as the adjacent "Paste & Audit" or "Run Launch Check" controls. Review state is **SERVER-backed**: it rides the EXISTING Turso workspace payload as **ADDITIVE fields** (per-row review entry: state + reviewer name + note + timestamp) saved via the existing debounced autosave PUT — **NO new table, NO schema migration, NO new credential**. A workspace saved BEFORE this feature (no review fields) still loads fine and simply shows **0 reviews** / every row Unreviewed. The owner and everyone on the workspace see a **full-width review roll-up SUMMARY panel ABOVE the grid** (normal page flow, NOT a side panel, NOT inside grid columns) reading e.g. **"12 approved · 3 need changes · 5 unreviewed"**; per row, a **review-state badge + reviewer name + note** render inline. **Mode-aware copy:** the review surface is server-persisted on the shared workspace — any "client-side"/"nothing leaves your browser"/zero-network wording near it must reflect that it is server-backed (no stale client-side-only claim). **Shareable READ-ONLY review summary at `/w/<id>/review`** (mirrors the existing `/w/<id>/guide` and `/w/<id>/check` read-only pages): server-data-derived, reuses **GET `/api/workspace/<id>`**, **strictly GET-only — NO mutation, NO POST/PUT, never autosaves, never writes localStorage**. It renders the approval status of EVERY link (state badge + reviewer + note) plus the roll-up counts, for a stakeholder who just needs to see "is this campaign signed off yet" — the viral on-ramp; it carries a clear **prominent CTA** to the editable `/w/<id>`. The editable `/w/<id>` page exposes a first-class, visually distinct **"Share review summary"** action (NOT buried) that copies the `/w/<id>/review` link with a peripherally-unmissable **"Copied!"** confirmation. A nonexistent workspace id on `/w/<id>/review` shows a **"Workspace not found"** state with a link back to the builder (mirrors `/w/<id>` not-found), never a crash/blank. None of this exists off `/w/` pages — the main builder, Rung 1 share link, Campaigns library, presets, UTM Spec, bulk ops, and CSV are unchanged and a cold open shows no review surface. Free-tier: Turso only (additive payload fields), no RESEND, no Stripe, no new env var. Reachable/operable in the mobile card view at 375px (the roll-up panel, per-row review control, reviewer-name control, and "Share review summary" stack with no horizontal scroll and no sticky/overlay occlusion).
   - **My Workspaces — device-local personal workspace index (anonymous-first, main builder `/` ONLY).** Today the secret `/w/<id>` link is the ONLY handle on a Team Workspace — lose the link, lose the workspace. This rung gives a marketer/agency managing many campaigns a personal, 100% client-side index of every workspace they CREATED or OPENED, so they can find them again — with **NO Turso schema change, NO new server route, NO new credential, anonymous-first, and never blocking any cold-open flow**. **(a) Recording (automatic, local):** when the user successfully **Creates a Team Workspace** (the existing "Create shared workspace" POST → navigate to `/w/<id>`) OR opens a `/w/<id>` page that **RESOLVES to a real workspace**, the app upserts an entry into localStorage key **`utm-grid:my-workspaces`**: `{ id, label (the workspace editor label / derived name, fallback to id), role ("owner" if THIS browser created it, else "visited"), lastOpened (epoch), link (full https://<host>/w/<id> URL) }`. Opening an already-listed workspace updates `lastOpened` (and `label` if changed). A **"Workspace not found"** id is **NEVER** recorded. Recording happens in a client **EFFECT after the workspace resolves** — never in a useState lazy initializer or render-closure localStorage read (SSR/hydration-safe), and on `/w/<id>` it triggers **NO extra POST/PUT** and never interferes with autosave/last-write-wins. **(b) Surface (main builder `/` ONLY):** a first-class, visually DISCOVERABLE **"My Workspaces" panel at the TOP of the side area, AUTO-EXPANDED by default** (NOT buried/collapsed at the bottom). It lists entries **newest-by-lastOpened-first**, each with: label, a **role badge (Owner / Visited)**, a **relative last-opened time**, and per-entry actions **Open** (navigate to `/w/<id>`), **Copy link** (the full `/w/<id>` URL, with an unmissable **"Copied!"** confirmation that survives a re-render on the persistent trigger), and **Remove from list** (LOCAL only — does NOT call the server, does NOT delete or alter the actual workspace; confirm first).
