# UTM Grid
Purpose: a no-account, fully client-side bulk UTM campaign URL builder for marketers — edit 20–50 links in a spreadsheet-style grid with naming-convention linting and CSV round-trip.
Problem: A demand-gen / lifecycle marketer launching a campaign each week must tag 20–50 links with consistent UTM parameters across channels (email, paid social, organic social, partners), and a single casing/spelling inconsistency silently splits campaign data in GA4 — discovered only weeks later during reporting.
Beats alternative: Teamcamp UTM Bulk Link Creator (free, no account) — the best free bulk tool — requires hand-typed pipe-delimited per-row overrides, has no CSV import (links already live in a campaign planning sheet), no required-param or cross-row consistency linting (only a lowercase checkbox), and no presets. UTM Grid replaces pipe syntax with an editable grid, adds CSV import AND export for round-tripping with the existing campaign sheet, lints conventions as you type — including flagging near-duplicate values across rows (e.g. `spring_sale` vs `Spring-Sale`), the GA4 data-splitting failure no existing free tool catches — and saves channel presets in localStorage. Cuts a weekly 30-link batch from ~15 min to ~5 min.

Core flows:
1. **Edit links in a grid with lint-as-you-type.** The page opens on an editable spreadsheet-style grid: one row per link, columns for base URL, utm_source, utm_medium, utm_campaign, utm_term, utm_content, and a read-only generated-URL column that updates live. Rows can be added, duplicated, and deleted. Linting runs on every edit and marks offending cells with a visible warning (icon/color + hover or inline message): (a) required params missing — utm_source, utm_medium, utm_campaign required by default, toggleable; (b) case/space rules — lowercase-only and no-spaces on by default, each toggleable; (c) cross-row consistency — values in the same UTM column that match after normalizing case and separators (`-`, `_`, space) but differ literally are flagged on every affected cell, naming the conflicting variants; (d) **off-spec values (governed UTM taxonomy)** — a **UTM Spec panel** lets the user define, per UTM field (utm_source / utm_medium / utm_campaign / utm_term / utm_content), a list of canonical **allowed values** (the org's taxonomy). When a field has a non-empty allowed-value list: the cell input offers those values as autocomplete suggestions (HTML datalist), and any non-empty cell value not in the list (compared case-insensitively) is flagged with an **off-spec** lint warning that names the **nearest allowed value** (closest by normalized match, else shortest Levenshtein edit distance) and offers a one-click **"Fix to <nearest>"** action that sets the cell to that allowed value and re-runs lint. Off-spec linting is additive to the case/space/cross-row rules and toggleable like them (a single "Enforce UTM Spec" toggle; when off, no off-spec warnings and no datalist suggestions). A copy button per row copies the generated URL; a copy-all button copies all generated URLs. **Responsive layout (mobile card view, ≤640px):** the grid is purely CSS-responsive (Tailwind breakpoint classes — no JavaScript viewport detection, so no SSR/hydration mismatch and no double-mounted dual-layout component). On wide viewports (`sm` and up) the spreadsheet-style table renders unchanged. On narrow viewports (≤640px) each row renders instead as a vertical **card**: every UTM field is a stacked label-over-input pair (so no horizontal scrolling is needed to reach a field), the generated-URL and per-row copy/duplicate/delete/select controls are full-width and tap-friendly (≥44px touch targets), and lint warnings render inline under their field. All controls remain reachable and hittable on a phone — no sticky/overlay element occludes a checkbox or button. The bulk toolbar, Campaigns/UTM Spec/preset panels, Import/Export, and "Copy share link" all stack and stay reachable on mobile. A shared grid opened from a copied share link renders in this card view on a phone and is fully legible and usable. **Bulk row/column operations (power-edit, fully client-side):** each row has a selection checkbox plus a header "select all" checkbox, so bulk actions target either all rows or just the currently-selected subset (when no rows are selected, bulk ops apply to all rows). A bulk toolbar exposes two operations, each on a chosen UTM column (utm_source / utm_medium / utm_campaign / utm_term / utm_content): (a) **Set column** — set that field to one entered value across the targeted rows in a single action (an empty value clears the field across them), so a weekly 20–50 link batch that shares utm_campaign/source/medium is tagged in one move instead of per-row; (b) **Find & replace in column** — replace a value or substring in that column across the targeted rows (e.g. `Spring-Sale`→`spring_sale` everywhere). Both operations run instantly, persist to localStorage like the rest of the grid, trigger no network request, and re-run linting immediately so cross-row consistency and case/space warnings update on the affected cells. The bulk controls use verbs distinct from the per-row controls (Set / Replace vs the row Dup / Delete) so they never read as duplicate controls.
2. **CSV round-trip with an existing campaign sheet.** An Import CSV button accepts a file upload, parses it in the browser, shows a column-mapping step (map CSV headers to base URL and each utm_* field; headers matching field names are pre-mapped), and populates the grid — lint warnings apply immediately to imported rows. An Export CSV button downloads a file with one row per grid row containing the base URL, every utm_* column, and the full generated URL. Exporting and re-importing the same file reproduces the grid exactly.
3. **Named saved state in localStorage — channel presets AND a Campaigns library.** Two complementary kinds of reusable saved state, both 100% client-side (localStorage only — no accounts, no server, no network):
   - **Channel presets:** save the current values of any subset of UTM fields (e.g. utm_source=facebook, utm_medium=paid_social) as a named preset ("Paid Social"), then apply a preset to a selected row or to new rows so weekly batches start pre-filled.
   - **UTM Spec (governed taxonomy):** the per-field allowed-value lists and the "Enforce UTM Spec" toggle persist in localStorage alongside presets/campaigns, are saved INSIDE each named campaign's state, and ride inside the share-link fragment (Flow 4) — so opening a saved campaign or a shared grid adopts that grid's UTM Spec, propagating the team's taxonomy. This is the convention-propagation loop: one marketer defines the org taxonomy and shares it; the teammate's grid then enforces it.
   - **Campaigns library (personal-accumulation layer):** save the ENTIRE current grid — every row (base URL + all utm_* fields), the active lint-rule toggles, AND the current UTM Spec (allowed-value lists + enforce toggle) — as a NAMED campaign (e.g. "Black Friday"), building up a reusable library the user returns to each week. A Campaigns panel lists saved campaigns by name with their link count and last-saved time. From it the user can: **Open** a campaign (load it as the working grid, with the same unsaved-edits guard the share-link load uses — confirm before replacing a dirty working grid), **Save as campaign** (name + save current grid; saving under an existing name updates it after a confirm-overwrite), **Duplicate** a campaign (copies to "<name> copy"), and **Delete** a campaign (confirm). A first-ever visit shows an empty library with a one-line hint.
   - Presets, the Campaigns library, lint-rule toggles, and the live working-grid rows themselves all persist in localStorage across reloads (a refresh mid-edit never loses the batch). Opening a saved campaign or a share link never silently clobbers unsaved working-grid edits.
   - From the Campaigns panel the user can also **Rename** a campaign: clicking Rename reveals an inline pre-filled name field (Enter commits, Esc cancels); the campaign's id, rows, and settings are unchanged; renaming to the same name is a no-op; renaming to a name that collides with a different campaign prompts a confirm-overwrite dialog before replacing. A search/filter input at the top of the Campaigns list filters visible cards by name substring (case-insensitive).
4. **Share the whole grid by link (client-side, no account, no server).** A "Copy share link" button encodes the entire current grid state — every row's base URL and all utm_* fields, the active lint-rule toggles, AND the current UTM Spec (per-field allowed-value lists + the "Enforce UTM Spec" toggle) — into the URL fragment (hash), compressed, and copies the full shareable URL to the clipboard with a peripherally-unmissable "Copied!" confirmation. Nothing is sent to any server (the state lives only in the hash). Opening a URL that contains a share fragment rehydrates the grid to exactly the shared state — including the shared UTM Spec, which then governs off-spec linting and datalist suggestions for the visitor — and shows a "Loaded shared grid (N links)" confirmation; the visitor's own localStorage is not overwritten until they edit. This turns a single-user batch into a team handoff — a marketer sends a teammate a link instead of a CSV — while preserving the zero-network privacy prop.

Success checks:
- Entering base URL `https://example.com/sale`, utm_source `newsletter`, utm_medium `email`, utm_campaign `spring_sale` in a row shows `https://example.com/sale?utm_source=newsletter&utm_medium=email&utm_campaign=spring_sale` in that row's generated-URL column.
- Clearing utm_medium in a row (with default rules) shows a visible missing-required-param warning on that cell, and the warning disappears when a value is entered.
- Typing `Spring Sale` in utm_campaign (default rules) shows a lint warning on that cell mentioning uppercase and/or spaces.
- Entering `Spring-Sale` in utm_campaign when another row already has `spring_sale` shows a cross-row consistency warning on BOTH cells that names the conflicting variants; making the values identical clears the warning on both.
- In the UTM Spec panel, adding allowed values `twitter` and `facebook` for utm_source (with "Enforce UTM Spec" on), then typing utm_source `twiter` (a typo) in a row shows an off-spec lint warning on that cell that names the nearest allowed value `twitter`; clicking "Fix to twitter" sets the cell value to `twitter` and the off-spec warning disappears.
- With utm_source allowed values `newsletter`,`facebook` and Enforce UTM Spec on, the utm_source cell input exposes those values as datalist autocomplete suggestions; typing an exactly-allowed value (`newsletter`) shows no off-spec warning.
- Toggling "Enforce UTM Spec" off removes all off-spec warnings and the datalist suggestions; toggling it back on restores them. The UTM Spec (allowed-value lists + enforce toggle) persists across a page reload.
- Defining a UTM Spec (utm_source allowed `newsletter`,`facebook`), saving the grid as campaign `Q3 Taxonomy`, reloading, clearing/altering the spec, then Open `Q3 Taxonomy` restores the saved spec (utm_source allowed values back to `newsletter`,`facebook`) so the loaded grid enforces that taxonomy.
- Building a 3-row grid with utm_campaign empty in all rows, then in the bulk toolbar choosing column `utm_campaign`, entering `black_friday`, and clicking **Set column** (with no rows selected → applies to all) sets utm_campaign to `black_friday` in all 3 rows at once and updates each generated-URL cell to include `utm_campaign=black_friday`; the change persists across a page reload.
- Selecting only rows 1 and 3 via their checkboxes, then Set column `utm_source` to `newsletter`, sets utm_source to `newsletter` in rows 1 and 3 only and leaves row 2 unchanged; the header "select all" checkbox selects/clears every row's checkbox.
- With rows containing utm_campaign values `Spring-Sale` and `spring_sale` (a cross-row consistency warning visible on both), choosing column `utm_campaign`, Find `Spring-Sale` Replace `spring_sale`, and clicking **Find & replace in column** makes both values literally `spring_sale` and the cross-row consistency warning disappears from both cells (lint re-runs immediately).
- Doing a Set column with an empty value clears that utm field across the targeted rows (the cells become empty and, if the field is required, a missing-required-param warning appears on them).
- The bulk Set / Find & replace operations trigger no network request (verifiable in the DevTools Network tab after initial page load).
- Clicking Export CSV downloads a CSV containing one row per grid row with columns for the base URL, each utm_* parameter, and the full generated URL.
- Importing a CSV with headers `url,source,medium,campaign` opens a column-mapping step; after mapping, the grid contains one row per CSV data row with those values, and lint warnings appear on any imported values that violate the rules.
- Exporting the grid to CSV and importing that file back reproduces the same rows and values (round-trip).
- Saving a preset named `Paid Social` with utm_source `facebook` and utm_medium `paid_social`, reloading the page, and applying it to an empty row fills utm_source and utm_medium with those values.
- Building a 2-row grid (row 1 base `https://example.com/a` utm_source `newsletter`; row 2 base `https://example.com/b` utm_source `twitter`), clicking "Save as campaign" and naming it `Black Friday`, shows `Black Friday` in the Campaigns panel listing 2 links; reloading the page, then clicking Open on `Black Friday`, restores exactly those 2 rows with those base URLs and utm_source values.
- With campaign `Black Friday` saved, editing the working grid to different values and clicking Open on `Black Friday` prompts to confirm before replacing the unsaved working grid (it does not silently discard the current edits); confirming loads the saved campaign, cancelling leaves the current grid untouched.
- Saving the current grid under the name `Black Friday` a second time (after edits) prompts a confirm-overwrite and, on confirm, updates the existing `Black Friday` campaign in place rather than creating a duplicate; the Campaigns panel still shows a single `Black Friday` entry with the new link count.
- Clicking Duplicate on `Black Friday` creates a `Black Friday copy` entry with the same rows; clicking Delete on it (and confirming) removes it from the panel, and both changes persist across a reload.
- Saving a campaign named `Black Friday` with 2 links, then clicking Rename and entering `BF 2026` (Enter to commit), updates the card name to `BF 2026` in place, still shows 2 links, and persists across a page reload; the id is unchanged so the "In: BF 2026" pill also reflects the new name if that campaign is open.
- A first visit (empty localStorage) shows an empty Campaigns library with a one-line hint and no saved campaigns.
- Saving, opening, duplicating, and deleting a campaign trigger no network request (verifiable in the DevTools Network tab after initial page load).
- Filling rows and reloading the page restores the same rows (grid edits persist in localStorage); a first visit shows a single empty starter row.
- Entering base URL `https://example.com/p?utm_source=old` with utm_source `src` shows a lint warning on the Base URL cell naming `utm_source`, and the generated URL contains `utm_source=src` exactly once — the grid value replaces the pre-existing param instead of appending a duplicate.
- The page has no login or signup, and editing, importing, and exporting trigger no network requests (verifiable in the browser DevTools Network tab after initial page load).
- Building a 3-row grid with distinct values AND a UTM Spec (utm_medium allowed `email`,`paid_social`, Enforce on), clicking "Copy share link", then opening the copied URL in a fresh/incognito tab shows the same 3 rows with identical base URLs, utm_* values, the same lint warnings, AND the shared UTM Spec in effect (a utm_medium value not in `email`,`paid_social` shows an off-spec warning in the fresh tab); a "Loaded shared grid (3 links)" confirmation is visible. Clicking "Copy share link" shows a clearly visible "Copied!" confirmation, and the click triggers no network request.
- Opening a share link does not overwrite the visitor's pre-existing localStorage grid until the visitor edits a cell (so a teammate previewing a shared grid does not lose their own in-progress batch by merely opening the link).

- At a 375px-wide viewport (a phone), the grid renders as stacked vertical cards — one card per row — with NO horizontal page scroll required to read or edit any UTM field; each field shows its label above its input. (At ≥640px the spreadsheet table renders instead.)
- At 375px, every per-row control — the row selection checkbox, copy, duplicate, and delete — is fully tappable (not occluded by any sticky/overlay element) and at least ~44px in its tappable dimension; tapping each performs its action.
- At 375px, the bulk toolbar (column picker + value + Set / Find & replace), the Campaigns panel, the UTM Spec panel, Import/Export CSV, and "Copy share link" are all reachable and operable without horizontal scrolling.
- Opening a copied share link on a 375px viewport rehydrates the grid and renders it in the mobile card view, fully legible (the "Loaded shared grid (N links)" confirmation is visible and each shared row's fields are readable without horizontal scroll).
- The desktop spreadsheet table layout and all its behaviors are unchanged at ≥640px (resizing a desktop browser from wide to narrow swaps table↔cards with no loss of grid state).

Out of scope:
- Accounts, auth, payments, or any server-side storage (no Turso, no API routes — fully client-side).
- Server-side or account-based team-shared convention configs (the utm.io/Terminus pay feature). Grid sharing is client-side via the URL fragment only — no server, no account, no stored share registry.
- Link shortening, click tracking, QR codes, or analytics integrations (no GA4 API).
- Direct Google Sheets / Excel integration (CSV files only).
- Single-base-URL parameter-matrix expansion (the Groot Solutions bulk mode).
- Destination-URL reachability checks (basic URL format validation only).
